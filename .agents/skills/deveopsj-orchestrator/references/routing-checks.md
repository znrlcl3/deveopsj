# 하네스 라우팅 검증

하네스 변경 시 아래 요청을 읽고 필요한 역할·실행 방식·검증이 연결되는지 점검한다. 이는 문서 기반 모의 실행이며 실제 코드 변경, 별도 에이전트 실행 또는 스킬 적용/미적용 A/B 실험을 대체하지 않는다.

## 적용 사례
| 요청 | 예상 역할과 확인할 행동 |
| --- | --- |
| 지출 수정에 다른 회원 ID를 보내면 막아줘 | Domain + Web + QA, 서비스/쿼리 소유권과 MockMvc |
| 반복 납입의 2월 말 확정을 수정해줘 | Domain + QA, 월말/윤년/중복 확정 |
| 월별 매수와 매도 현금흐름이 틀려 | Domain + QA, 현금흐름과 잔존 원가 구분 |
| 카드 명세서를 다시 올리면 중복 등록돼 | Domain + Web + QA, 거래 키/DB 충돌과 미리보기 재전송 |
| 카드 가맹점 분류에서 없는 코드를 반환해 | AI + Domain + QA, 활성 codeId와 배치 누락/fallback |
| KIS 환율이 느려서 포트폴리오가 멈춰 | Market + Domain + QA, timeout/캐시/대체 환율, 표시 변경 시 Web |
| Nasdaq 종목 동기화 실패를 처리해줘 | Market + Domain + QA, 부분 실패/기존 거래 참조 |
| Keycloak 로그인 후 권한이 잘못돼 | Web + QA, OIDC 역할/계정 연결, 프로필 문제면 Operations |
| OPA가 꺼지면 타인 지출도 수정돼 | Web + Domain + QA, 비활성/장애 구분과 항상 유지할 소유권 |
| prod 설정과 SQL 배포 순서를 정리해줘 | Operations + Domain + QA, 준비 파일 검증, 실제 DB 적용은 요청 범위 확인 |

## 경계 사례
| 요청 | 예상 행동 |
| --- | --- |
| 하네스 있어? | 구성 확인/설명, 구현 흐름 실행 안 함 |
| 하네스 다시 설계해줘 | harness/skill-creator로 지침 재설계, 애플리케이션 자동 수정 안 함 |
| Java BigDecimal이 뭐야? | 직접 설명, 프로젝트 전체 테스트 안 함 |
| 내가 커밋할까? | Git 명령 없이 알려진 맥락으로 메시지 안내 |
| 방금 작업 커밋해줘 | 명시적 커밋 요청 처리, 사용자 변경 자동 포함 안 함 |
| README 오타만 고쳐줘 | 문서 수정/차이 검증, Maven 전체 테스트 안 함 |
| 포트폴리오 계산식만 고쳐줘 | Domain 주도, 외부 클라이언트까지 불필요하게 재작성 안 함 |
| Gemini와 시세 오류 메시지를 둘 다 고쳐줘 | AI/Market/Web 순차 적용, 다중 경계라는 이유만으로 병렬 실행 안 함 |
| 전문가들을 병렬로 써줘 | 환경 도구/지침 확인 후 독립 파일 분담, 공유 계약은 순차 통합 |
| 환율 표시만 다시 확인해줘 | 이전 diff의 DTO/화면 상태 계약 재검증, 전체 재설계 안 함 |

## 실패 흐름
1. OPA timeout을 시세 stale fallback처럼 허용으로 처리하면 실패다. Web 인가 규칙으로 돌아가 거부 경로를 확인한다.
2. Maven이 DB 연결로 실패하면 통과라고 보고하지 않는다. 실행된 테스트와 DB 의존 검증을 분리한다.
3. 위임 실패 시 확인되지 않은 결과를 만들지 않는다. 부분 결과와 누락을 회수하고 독립 작업만 계속한다.
4. 문서만 고친 작업에서 외부 Gemini 호출이나 운영 SQL 적용을 시도하면 범위 이탈이다.

## 2026-10-12 검토 기록
위 20개 요청과 4개 실패 흐름을 새 오케스트레이터·역할 스킬에 대조해 문서 기반 모의 검토했다. 기본 순차 실행, 커밋 안내, Domain/Market 계산 경계, AI fallback과 OPA 거부 정책이 연결된다.
별도 에이전트 행동 실험과 A/B 비교, Maven/OPA 실행 검증은 이번 문서 재설계에서 수행하지 않았다. 실제 업무에서 잘못 배정되거나 누락된 사례가 확인되면 해당 경계만 보완한다.
