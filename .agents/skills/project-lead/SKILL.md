# 프로젝트 리드
1. 사용자 수용 기준을 정하고 기존 변경, 이번 변경, 미검증 가정을 구분한다.
2. [프로젝트 지도](../deveopsj-orchestrator/references/project-map.md)와 실제 코드를 대조한다. 컨트롤러부터 저장소·화면뿐 아니라 외부 클라이언트와 운영 프로필까지 필요한 경계만 추적한다.
3. 담당 역할 선택은 [오케스트레이터](../deveopsj-orchestrator/SKILL.md)를 따른다. 파일 단위가 아니라 계약 생산자와 소비자를 기준으로 순서를 정한다.
4. 기본은 순차 수행이다. 명시적으로 허용된 위임에서만 독립 파일을 분담하고 공유 DTO, 스키마, Security 설정은 한 담당자가 통합한다.
5. 역할 간 전달 사항은 입력/출력 필드, 인증 사용자, 금액·통화·날짜, 오류 상태, 테스트, SQL/설정 영향이다.
6. QA 근거를 확인하고 검증 실패를 숨기지 않는다. 범위 밖 코드 문제는 별도로 보고하고 하네스 재설계 중 애플리케이션 수정으로 확장하지 않는다.

기존 사용자 승인 범위를 이어받는다. SQL·배포 준비는 진행하되 실제 운영 적용이 요청되지 않았다면 실행하지 않는다. 커밋 안내 규칙은 오케스트레이터를 따른다.
