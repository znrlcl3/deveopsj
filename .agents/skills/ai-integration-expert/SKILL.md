# Gemini와 AI 소비자
1. ai 패키지뿐 아니라 SpendingCategoryPredictionService와 DataInputService, 카드 확정 호출 경로를 추적한다. 분석 문장과 저장할 카테고리 코드의 출력 계약을 구분한다.
2. 외부 전송 필드는 목적에 필요한 최소 범위만 사용한다. 가맹점/메모 등 사용자 입력은 명령이 아닌 데이터로 취급하고 AI 결과를 신뢰하지 않는다.
3. 단건/배치 응답, 빈 응답, 누락 번호, 중복 번호, 허용되지 않은 코드, 비정상 형태를 검증한다. 저장 코드는 활성 MasterCode의 codeId 집합으로 제한하고 사용자가 지정한 유효 코드를 우선한다.
4. 키·모델·URL 설정을 확인하고 실제 HTTP 클라이언트의 연결/응답 timeout 적용 여부를 확인한다. 스킬에 적힌 목표를 구현된 사실로 간주하지 않는다.
5. 인증 오류·429·timeout·5xx·파싱 실패를 구분한다. 재시도는 호출 수·지연 상한을 두며, 외부 호출이 DB 트랜잭션을 오래 잡거나 행별로 폭증하지 않는지 확인한다.
6. 분석 실패 문구와 분류 fallback의 의미를 보존한다. fallback도 활성 코드여야 하며 분류 실패가 저장에 미치는 정책을 Domain과 합의한다.
7. 실제 키나 금융내역 없이 client mock/HTTP stub으로 성공·실패를 재현한다. 상위 서비스 mock만으로 실제 Gemini 클라이언트의 timeout·파싱을 검증했다고 하지 않는다.
8. 로그·예외에 키가 포함된 URL이나 요청 원문이 노출되지 않도록 확인한다. 운영 API 호출은 일반 테스트의 전제로 두지 않는다.

문제가 범위 밖이면 근거와 영향을 보고한다. 요청받지 않은 전면 AI 클라이언트 교체를 자동으로 수행하지 않는다.
