# 가계부 화면 설계와 리뷰

1. [공통 작업 범위](../../../AGENTS.md)에 따라 리뷰 요청에는 관찰·근거·개선안만 제공한다. 화면 구현 요청은 합의한 변경과 확인 조건을 Web에 전달한다. 현재 템플릿·스타일·연결 화면과 사용자가 제공한 마스킹 자료에서 확인한 범위를 밝힌다. 환경이나 DB 부작용이 불명확한 앱에 접속하거나 폼을 제출해 확인하지 않는다.
2. 사용자가 이 화면을 연 이유를 한 문장으로 정하고 첫 화면의 제목·요약·주요 버튼이 그 일로 이어지는지 살핀다. 오늘 처리할 항목, 예정, 완료·0건을 구분한다. 같은 행동은 찾기 쉬운 한 곳에 두고, 대기·완료 상태는 짧게 표시한다.
3. 메뉴나 입력 경로를 바꿀 때는 진입 → 선택 → 확인 → 복귀를 따라가며 현재 탭, 조회 월, 버튼 목적지와 오류 뒤 입력 보존을 검토한다. 공통 헤더·탭의 위치, 좁은 화면의 읽기 순서, 키보드 포커스·레이블, 색상 없이도 구분되는 상태를 변경 범위에서 확인한다.
4. 금융 문구는 실제 데이터가 증명하는 상태로 쓴다. 납입 기록이 없는 경우에는 ‘납입 여부 확인’, 급여 추정액에는 ‘예상’처럼 표시한다. 금액의 의미나 분류 기준을 바꿔야 하면 Domain에 연결한다.
5. 리뷰 결과는 영향이 큰 항목부터 화면 위치·불편·권장 변경·수용 기준을 짝지어 제시한다. 예를 들어 오늘까지인 미확정 지출이 있을 때 첫 행동으로 나타나는지와 0건일 때 다음 행동이 무엇인지를 함께 적는다. 실제로 보지 못한 화면은 확인 완료로 보고하지 않는다.
