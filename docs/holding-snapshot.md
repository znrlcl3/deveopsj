# 현재 보유분 입력

`/holdings/form`에서 본인 플랜과 활성 종목을 선택하고 수량·평균 매수가를 입력한다.
국내 종목은 원화/환율 1을 서버에서 고정한다. 해외 종목은 종목 통화의 평균 매수가와 매입 환율을 받는다.
원화 원금은 수량 × 평균 매수가 × 환율을 원 단위 HALF_UP 반올림한다. 수수료/세금은 추가하지 않는다.

## 반영 기준

- 기존 asset_trade에 SNAPSHOT 유형으로 오늘 날짜의 잔고 기준을 기록한다. 날짜·통화·사용자는 서버가 정한다.
- 플랜·종목별 날짜/ID 순으로 계산하며 SNAPSHOT에서 수량과 원가를 교체한다. 이후 BUY/SELL은 기존 이동평균법으로 반영한다.
- 같은 날 먼저 등록한 매매는 새 잔고에 포함된 것으로 간주한다. 이후에는 잔고에 포함되지 않은 새 거래만 등록한다.
- 재등록/동일 요청 재전송은 합산되지 않는다. 등록 이력은 남으며 마지막 기록이 기준이 된다.
- 과거 월의 보유 원가는 유지된다. 기준 등록 전의 거래를 나중에 수정해도 현재 잔고 기준에는 영향을 주지 않는다.
- 납입·목표 달성 원금·월별 매수/매도액·현금흐름에는 기준 원금을 더하지 않는다. 초기 계좌 현금 잔액이나 과거 전체 투자수익률을 복원하는 기능이 아니다.
- 매매 내역에 '보유분 기준 등록'으로 표시한다. 잘못 입력하면 새 잔고를 입력하거나 해당 기준 기록을 삭제한다. 삭제 시 이전 기준/매매 계산으로 돌아간다.
- 평균 매수가 입력은 양수 보유분용이다. 전량 매도는 매매 등록을 사용한다.

## 배포

운영 `ddl-auto=validate` 환경은 새 앱 실행 전에 `deploy/sql/20261105_add_holding_snapshot.sql`을 적용한다.
기존 enum에 SNAPSHOT을 추가한다. 이전 앱은 SNAPSHOT을 읽지 못하므로 구버전과 혼용하지 않는다.
SQL 작성과 실제 DB 실행은 별개이며 이 변경에서 실제 DB에는 적용하지 않았다.
