# 나무 종합거래내역 가져오기

투자 거래내역 → 엑셀 가져오기(`/trades/import`)에서 사용한다.

1. **나무증권 → 뱅킹/계좌정보 → 거래내역 → 종합거래내역**에서 종합거래내역(간략)을 내려받는다.
2. 해당 계좌의 플랜과 파일을 선택한다. 원본 HTML 형식 `.xls`(UTF-8/MS949), 같은 13열을 유지한 실제 XLS/XLSX 한 시트를 지원한다. 5MB, 2,000 데이터행까지이며 수식/암호화는 지원하지 않는다.
3. 매수·매도의 종목 후보와 분배금·이자 수입을 확인하고 저장할 행을 선택한다. 중복이 없고 저장 대상이 하나인 매매·입출금·분배금·이자는 자동 선택하며, 그 외에는 저장 안 함으로 시작한다. 실거래일자를 기준으로 저장한다.

## 저장 정책

- 국내 코스피·코스닥 매수/매도, 입금 유형의 ETF분배금입금·예탁금이용료를 지원한다. ETF 분배금은 DIVIDEND(배당·분배금), 예탁금 이용료는 INTEREST(이자) 수입으로 저장한다. 입금/이체입금, 출금/이체출금은 AccountTransfer에 별도로 저장한다. 미국 USD 주식·ETF 매매는 별도 해외주식거래내역으로 저장하며, USD 배당·이자·외화 이체입출금은 계좌 기록으로 별도 저장하며 환전과 다른 통화는 제외한다.
- 단가×수량=거래금액, 거래금액±비용=정산금액을 검증한다. 수수료·세금은 원화 정수로 보존한다.
- 종목코드가 없어 활성 KRW 국내 종목의 이름으로 후보를 찾는다. 복수 후보는 사용자가 시장·코드를 확인한다. 없는 종목을 이름만으로 새로 만들지 않는다.
- 같은 플랜의 최신 보유분 기준일 이전/당일 거래는 `historyOnly=true`: 월별 매매 합계에는 포함하지만 현재·월말 수량과 원가 계산에서 제외한다. 기준 기록을 나중에 삭제해도 이 표시는 유지되며 과거 수량으로 재해석하지 않는다. 당시 월말 잔액 복원용 데이터가 아니다.
- 기준 이후/기준 없는 종목은 보유수량에 반영하며 이전 매수가 누락되어 수량이 음수가 되면 선택 거래 전체를 저장하지 않는다. 같은 날 가져오는 거래는 매수부터 저장하며 체결 시각·실현손익의 정확한 재현은 지원하지 않는다.
- 같은 파일 내 동일 거래는 모두 중복 확인 대상으로 표시한다. 플랜별 원본 거래 필드의 SHA-256 키와 DB unique 제약으로 미확인 재등록을 차단한다. 기존 수기 입력과 날짜/종목/수량/단가/비용이 같아도 중복 의심으로 제외한다. 별도 실제 체결이면 미리보기에서 행별 확인 체크 후 추가 등록한다.
- 플랜 단위 잠금으로 여러 가져오기와 보유분 등록을 직렬화한다. 미리보기 때와 기준이 달라지면 재업로드를 요구한다. 기존 수기 매매의 동시 수정까지 완전히 직렬화하는 기능은 아니다.
- 미리보기는 인증 세션에 10분 저장하며 회원/토큰/행/종목을 서버에서 재검증한다. 원본 파일 전체는 회원·플랜별 DB 보관함에 저장한다. 미리보기 세션 만료와 별개로 보관한다. 저장 성공 후 미리보기는 소비한다.
- 가져온 거래는 수정 대신 삭제 후 재업로드한다. 삭제하면 importKey도 삭제되어 다시 가져올 수 있다. ‘내역만 저장’ 행을 삭제해도 보유분은 바뀌지 않는다.
- 투자 거래내역 목록은 매매와 계좌 입출금을 별도 표로 표시한다. SNAPSHOT은 하단 ‘보유분 기준 기록 (매매 아님)’에 분리하고 날짜를 ‘보유분 기준일’로 표시한다. 저장일을 실제 매수일로 오인하지 않도록 한다.

## 운영 적용

`deploy/sql/20261105_add_trade_import.sql`을 한 번 적용 후 앱을 시작한다. `history_only`는 기존 행에 false, `import_key`는 NULL로 추가되어 기존 매매 동작은 유지된다. 이 SQL은 자동 실행하지 않았다.

## 수입 가져오기와 원본 상세

- 수입은 정산금액(실제 입금액) 기준이다. 세전 거래금액 - 수수료 - 세금 = 정산금액을 검증하며 0 이하 입금액은 저장하지 않는다.
- 종목명, 원본 상세내용, 실거래일(수입일), 원본 거래일자, 세전 거래금액, 수수료, 세금, 등록 시 플랜 이름·ID를 보존한다. 예탁금 이용료는 종목명이 없어도 처리한다. 수입 엔티티에는 원본 파일을 넣지 않는다. 원본 파일 전체는 별도 회원 전용 보관함에 저장하므로 파일 안의 원본 정보도 보존된다.
- 수입 목록의 ‘나무 원본 상세내역’에서 확인한다. 원본을 보존하기 위해 가져온 수입은 수정 대신 삭제 후 재업로드한다. 삭제 후 재업로드는 가능하다.
- 회원/플랜/날짜/유형/종목/금액/비용 기반 키의 DB unique 제약으로 재업로드를 방지한다. 동일 파일 내 반복은 확인 전까지 선택을 막는다. 같은 회원의 같은 날짜·유형·실입금액인 수기 수입은 중복 의심으로 제외한다. 서로 다른 종목·플랜의 정상 수입을 원본 구분 없이 합치지 않는다.
- 저장할 때 중복을 다시 확인한다. 회원 잠금으로 수기 수입 저장·수정·삭제와 가져오기를 직렬화한다. 선택한 매매·입출금·수입은 하나의 트랜잭션으로 저장한다.
- 수입 등록만으로 계좌 잔액이나 보유 주식 수량을 늘리지 않는다. 수입 합계·대시보드·현금흐름은 기존 Income 집계를 사용한다.
- 추가 스키마: `deploy/sql/20261105_add_namuh_income_import.sql`을 한 번 적용해야 한다. 기존 수기 수입의 필드는 유지하며 운영 DB에 자동 적용하지 않았다.

## 미리보기 기본 선택

저장 대상이 정확히 하나이고 중복이 아닌 매매·입출금·분배금·이자를 자동 선택한다. 후보가 여럿이면 중복 후보를 빼고 하나만 남아도 자동 선택하지 않는다. 중복 의심·오류 행은 빨간 배경과 사유를 표시하고, 복수 종목 후보는 노란 배경으로 직접 선택을 안내한다. 사용자는 저장 안 함으로 제외할 수 있으며 저장 버튼을 눌러야 등록된다. 저장 직전에 중복을 다시 검사하므로 다른 미리보기에서 먼저 저장한 거래는 다시 등록되지 않는다. 원본에 거래 시각이 없어 거래일·종목·유형·수량·단가·비용으로 비교한다.

## 계좌 입출금과 유형별 조회

- 지원하는 조합은 거래유형 입금 + 상세내용 이체입금, 출금 + 이체출금이다. 다른 입출금성 거래를 임의 분류하지 않는다. 실거래일, 원본 거래일자, 원본 명칭/상세내용, 거래금액, 정산금액, 수수료·세금을 저장한다.
- 입금은 거래금액-수수료-세금, 출금은 거래금액+수수료+세금이 정산금액과 같은지 검증한다. 양수 원화 정산액만 허용한다.
- `account_transfer`는 Income, DailySpending, AssetTrade와 독립적이다. 수입·지출·현금흐름·보유수량·수익률·목표 진행률에 합산하거나 계좌 잔액을 자동 변경하지 않는다.
- 투자 거래내역에서 월과 전체/매수/매도/입금/출금 필터를 조합한다. 전체는 매매 표와 입출금 표를 함께 표시하며 입출금 필터는 매매·보유분 기록을 숨긴다. 기존 엑셀 내보내기는 변경하지 않았으며 매매·보유분 기록만 내보낸다.
- 같은 회원·플랜·실거래일·방향·원본 명칭·금액·비용의 입출금은 해시 키로 미확인 재등록을 막고, 저장 시에도 회원/플랜 잠금 안에서 다시 검사한다. 거래 시각·원본 고유번호가 없는 양식이라 같은 날 동일 금액의 실제 별도 입출금도 중복 의심으로 표시될 수 있다. 확인 체크 후 추가 등록할 수 있다. 다른 날짜/계좌/방향은 별도 내역이다.
- 원본 상세는 목록에서 확인한다. 본인 기록만 조회/삭제 가능하며 삭제에는 CSRF 토큰이 필요하다. 삭제 후 원본을 재업로드할 수 있다.
- 기존에 제외된 입출금은 원본 파일을 다시 업로드해 선택한다. 이미 등록한 매매/수입은 기존 키를 유지하므로 중복 등록되지 않는다.
- 운영 validate 설정에서는 `deploy/sql/20261109_add_account_transfer.sql`을 먼저 적용한다. SQL은 준비만 했으며 실제 DB에는 실행하지 않았다.

## 중복 의심 행 확인 등록

- 빨간 행에 파일 안 동일 조건 건수와 기존 저장 건수를 표시한다. 기본은 저장 안 함이며, ‘실제 별도 거래로 확인 · 이 행 추가 등록’을 체크하면 저장 대상을 선택할 수 있다. 대상이 하나면 체크 시 선택하고 체크 해제 시 선택을 지운다.
- 확인은 기존 기록에 해당 행을 추가하는 동작이다. 매매·입출금·분배금·이자에 동일하게 적용한다. 날짜·금액 오류나 연결할 종목이 없는 행은 확인으로 통과할 수 없다.
- 확인 후 등록한 행도 원본 조건 키(import_group_key)를 보존한다. 같은 파일을 재업로드하면 기존 저장 건수로 다시 경고하며 자동 선택하지 않는다. 다시 확인하여 저장하면 추가 기록이 생성되므로 실제 별도 거래에만 사용한다.
- 저장 직전 회원·플랜 잠금 안에서 기존 건수를 다시 비교한다. 미리보기 이후 건수가 바뀌면 확인 여부와 관계없이 전체 저장을 중단하고 재업로드를 요구한다. 거래 시각·고유번호가 없어 실제 별도 거래 여부는 사용자가 판단한다.
- 운영 DB는 기존 매매·수입 가져오기 SQL과 `20261109_add_account_transfer.sql` 이후 `deploy/sql/20261109_add_import_group_key.sql`을 한 번 적용해야 한다. 기존 import_key는 유지하며 과거 기록도 중복 검사한다. SQL은 준비만 했으며 실행하지 않았다.

## 해외 매매는 별도 해외주식거래내역으로 가져오기

같은 직투계좌 플랜에 두 양식을 구분해 업로드한다. 종합거래내역(간략)은 국내 매매·원화 입출금·분배금·이자만 저장한다. 종합 양식의 해외 매매는 확인 체크로도 등록할 수 없고 해외주식거래내역 업로드를 안내한다. 과거 간략 파일에서 이미 등록한 USD 매매도 같은 날·방향·수량이면 중복 의심으로 표시하므로 재등록에 주의한다.

해외주식거래내역은 15열, 두 줄 머리글, 거래 한 건당 두 행이다. 원본 HTML XLS, 실제 단일 시트 XLS/XLSX, 화면에서 복사한 탭 구분 TXT를 지원한다. 전체 두 행을 포함해야 한다. 5MB/2,000건 제한이다. 파일의 ISIN·통화·외화 거래액·정산액·비용·단가·수량·날짜를 검증하며 USD 매매만 등록한다. 단가×수량의 센트 반올림 차이는 최대 0.01 USD까지 허용하고 정산액은 비용 반영 값과 일치해야 한다. 원화로 별도 징수된 비용이 있는 매매는 확인 필요로 제외한다. USD 소수점해외배당금/소수점해외배당/외화배당금입금, 외화예탁금이용료, 외화이체입금/출금(또는 USD 이체입금/출금)을 별도 계좌 기록으로 지원한다. 정산액을 실제 외화 입출금액으로 사용하며 원본 세전액이 0인 행도 보존한다. 원화 세금은 상세 정보로 보존하고 USD에서 임의 차감하지 않는다. 환전과 원화 행은 제외한다.

- **금액:** 거래액·수수료·세금·정산액을 USD로 저장한다. 환율 입력은 없다. 파일에 있는 환율은 reference_exchange_rate와 원본 상세에 자동 보존한다. 실제 환전 비용과 차이가 있을 수 있으므로 환율 포함 손익에 사용할 때 거래내역 환율 기준으로 표시한다. 원화 환율·비용·정산액은 NULL(미확정)이다. 0원이나 환율 1로 대체하지 않는다. 기존에 실제 환율을 입력해 저장한 거래는 변경하지 않는다.
- **종목:** 회원별 저장된 ISIN 연결을 먼저 적용하고, 없으면 등록된 활성 미국 USD 종목명과 비교한다. 대소문자·공백·기호·AND/& 및 끝의 Common Stock 표기를 정리한 이름이 한 종목과 일치할 때만 자동 연결한다. 이름이 비슷하기만 하거나 동명 종목이 여러 개면 후보에서 선택한다. 종목명/티커 검색도 지원하며 임의 티커 추정이나 종목 자동 생성은 하지 않는다. 같은 파일의 같은 ISIN 행은 후보 선택을 공유한다. ID로 종목을 선택하여 동명/동일 티커의 시장 차이를 구분한다. 자동 또는 직접 선택한 종목을 저장할 때 활성 상태·USD·지원 시장을 재검증한다. 저장 성공 시 회원별 연결을 기억하며 같은 회원의 다른 플랜에서도 재사용한다. 다음 파일에서 유효한 연결이 있고 중복이 아니면 자동 선택한다. 비활성·지원하지 않는 종목은 자동 연결하지 않는다. 코드 변경은 이후 등록에만 반영하고 기존 거래는 바꾸지 않는다. 다른 회원의 연결은 조회·사용하지 않는다.
- **중복:** 상세 원본의 회원·플랜·거래일·ISIN·방향·수량·단가·금액·비용으로 키를 만든다. 표시 이름이나 입력 티커 변경으로 재등록을 우회하지 못한다. 기존 USD 매매의 날짜·방향·수량도 보수적으로 비교한다. 미리보기 후 건수 변화, CSRF/세션 토큰/선택 검증은 유지한다.
- **현재 평가:** 주가×수량×최신 환율로 원화 평가액을 보여준다. 환율 조회 실패 시 USD 원가에 임의 환율을 적용하지 않는다. 달러 기준 수익률을 별도 표시한다. 새 달러 거래의 이동평균 원가는 매수 비용을 포함한다. 매도 시 원가를 비례 차감한다. 매수환율 미확정 거래가 남아 있으면 확정 원화 원금·손익은 미확정으로 표시한다. 파일 환율이 있으면 USD 매수 정산액×파일 환율로 별도 원가를 계산해 환율 포함 손익을 표시한다. 파일 환율도 없으면 해당 손익은 표시하지 않는다. 현재 평가액과 목표의 자산평가액 진행률은 조회 가능한 최신 평가액을 사용한다.
- **월별·내보내기:** 투자 거래내역은 USD 정산액을 표시하고 원본 상세를 보존한다. 원화 월간 거래 합계·월말 원금이 미확정이면 표시하지 않는다. 월간 자금흐름은 원화 정산액 확인분만 집계하고 USD 제외를 안내한다. 엑셀 내보내기는 외화 금액·비용·정산액 열을 추가하고 미확정 원화 값은 빈칸으로 내보낸다.
- **DB:** 이전 SQL 이후 `deploy/sql/20261109_add_usd_trades_and_symbol_mapping.sql`을 한 번 적용한다. 기존 원화 필드의 NOT NULL 해제, 외화 금액 열, 회원별 ISIN 연결 테이블을 추가한다. 기존 데이터의 환율·금액은 덮어쓰지 않는다. SQL은 준비만 했으며 실제 DB에는 실행하지 않았다.

## IRP 계약 행

`매수 / 퇴직연금계약 / 개인 IRP`의 수량·단가는 0이므로 주식 매매가 아닌 계약 처리 안내로 제외한다. 대응하는 `입금 / 이체입금`은 기존 계좌 입금 기능으로 한 번 기록한다. 두 행을 각각 납입 원금이나 자산으로 더하지 않는다. 입금 기록 자체는 현재 잔액·목표 진행률을 자동 증가시키지 않는다. 향후 IRP 계좌의 납입 누계와 별도 평가액으로 관리하며, 실제 ETF 매매 자료가 있으면 해당 거래를 가져오는 방식이 적절하다.

## 계좌별 월간 거래와 손익 비교

계좌별 요약(`/assets/accounts`)에서 월을 선택하면 원화/달러별 매수·매도·배당·이자·이체입금·이체출금을 따로 본다. 환전·배당·매매 대금은 이체입출금에 중복 합산하지 않는다. 배당과 이자는 세후 정산액이며 USD 수입 기록은 원화 Income 집계에 합산하지 않는다. 현재 손익은 선택 월의 실현손익이 아니라 현재 보유분의 미실현 손익이다.

- 환율 제외: 현재 USD 평가액 − 이동평균 USD 원가.
- 환율 포함: 최신 환율을 적용한 평가액 − 매수 정산액에 파일의 거래 환율을 적용한 이동평균 원가. 파일 환율 사용 시 ‘거래내역 환율 기준’ 표시. 원화로 실제 등록한 거래는 기존 원가를 유지한다.
- 해외 배당·이자·입출금은 `foreign_account_entry`에 정산액과 원본 상세를 저장한다. 계좌별 요약에서 조회/삭제하며 회원 소유권·CSRF·회원 잠금을 적용한다. 중복 확인 등록 및 재업로드 검사도 동일하다.
- 추가 DB SQL: `20261109_add_usd_trades_and_symbol_mapping.sql` 이후 `20261109_add_foreign_account_flows.sql`. 실제 DB에는 실행하지 않았다.

## 업로드 원본 전체 보관

- 5MB 이하 파일과 본인 플랜을 확인하면 분석 전에 원본 바이트 전체를 DB에 보관한다. 지원하지 않는 행·환전·분석 오류 파일도 원본을 복원할 수 있다. 금융 집계 반영은 미리보기에서 선택 저장한 거래만 대상으로 한다.
- 회원+플랜+파일 SHA-256으로 같은 파일의 중복 보관을 막는다. 파일명만 바꿔 재업로드해도 같은 내용이면 기존 보관본을 사용한다. 다른 파일 형식/내용은 별도 원본으로 남는다.
- 가져오기 화면에서 최근 20개 보관 원본을 조회·다운로드한다. 소유 회원만 접근하며 다운로드는 attachment/octet-stream/no-store/nosniff로 제공한다. 서버 파일 경로를 사용하지 않는다.
- 과거 업로드의 원본을 소급 복원하지 않는다. 이번 기능 적용 후 다시 업로드한 파일부터 보관한다. SQL `deploy/sql/20261109_add_import_archive.sql`은 준비만 했으며 실행하지 않았다.

미국 Cboe BZX/IEX 종목도 연결·기록할 수 있다. 종목 연결과 시세 지원 범위는 별개이며 기존 시세 공급자가 지원하지 않는 시장은 현재가 조회 불가로 표시한다. 새 외부 시세 API나 ISIN 조회 API는 호출하지 않는다.
