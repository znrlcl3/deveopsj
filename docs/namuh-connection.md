# 나무증권 연결 및 운영 안내

사용자 화면: `/broker/namuh`. 보유자산 수익률, 보유분 입력, 매매 등록에서 접근할 수 있다.
사용자별 API 신청 → 키 등록 → 계좌 조회 → 잔고 미리보기/선택 반영 또는 월별 거래 조회 순서다.
화면의 사용 설명서는 최초 연결 전 펼쳐지고 연결 후에도 다시 열 수 있다.

## 사용자 준비

1. https://www.nhplug.com/howto-use 의 API 사용신청에서 본인 인증·약관 동의를 완료한다.
2. APPKEY와 APP Secret을 발급하고 이 앱 연결 화면에만 입력한다. 증권사 로그인/계좌 비밀번호는 받지 않는다.
3. 계좌 목록 불러오기 후 본인 계좌와 시장을 선택한다. 고객번호당 하나의 키로 여러 계좌를 이용할 수 있다.
4. 잔고는 미리보기에서 연결된 종목을 확인하고 계좌별 플랜을 선택해 반영한다. 다른 계좌의 같은 종목을 같은 플랜에 반영하면 기존 기준을 교체하므로 계좌별 별도 플랜을 사용한다.
5. 월별 매매 조회는 종합거래내역 원문 구분을 표시한다. 앱 장부에 저장하지 않는다.
6. 연결 해제는 앱의 암호화 키 정보와 토큰을 삭제한다. 증권사 키 폐기·서비스 해지는 나무 PLUG에서 별도로 한다.
회원 탈퇴·계정 비활성화 시에도 앱의 연결정보를 삭제한다. 활성 회원만 새 연결과 조회를 사용할 수 있다.

## 서버 설정

### 로컬 STS 실행

Git에서 제외된 `src/main/resources/application.properties`에 `app.namuh.encryption-key`를 설정할 수도 있다. 값은 동일하게 무작위 32바이트의 Base64이며 매 실행마다 새로 만들지 않는다. 이 로컬 속성은 `NAMUH_ENCRYPTION_KEY` 환경변수보다 우선하므로 운영 환경으로 복사하지 않는다.

설정 후 STS에서 기존 앱을 중지하고 다시 실행한 다음 `http://localhost:8080/broker/namuh`에 로그인해 접속한다. 서버 설정 경고가 사라지면 사용자가 나무 APPKEY/APP Secret을 화면에서 등록한다. 내부 암호화키와 나무 API 키는 서로 다른 값이다. 로컬 설정 파일을 덮어쓰거나 키를 잃으면 기존 연결을 해제하고 다시 등록해야 한다.

### 운영 및 공통 설정

- 새 버전 시작 전 `deploy/sql/20261105_add_namuh_connection.sql`을 적용한다. 보유분 등록에는 `20261105_add_holding_snapshot.sql`도 필요하다. 실제 DB 적용은 별도 작업이다.
- `NAMUH_ENCRYPTION_KEY` 환경변수: 암호학적으로 안전하게 생성한 32바이트를 Base64로 인코딩한 값. 모든 앱 인스턴스에서 같은 값을 사용한다. 저장소/채팅/로그에 기록하지 않는다.
- PowerShell 생성 예시(값은 표준출력에 내보내지 않는다):
  ```powershell
  $namuhKeyBytes = New-Object byte[] 32
  [System.Security.Cryptography.RandomNumberGenerator]::Fill($namuhKeyBytes)
  $env:NAMUH_ENCRYPTION_KEY = [Convert]::ToBase64String($namuhKeyBytes)
  ```
  앱을 이 환경을 상속하는 프로세스에서 시작한다. 운영은 보호된 환경설정/비밀 저장소에 영속 보관한다.
- 키가 없거나 형식이 잘못되면 등록·복호화를 거부한다. 하드코딩된 대체키나 자동 임시 키는 없다. 암호화키 분실/변경 시 기존 연결을 복호화할 수 없으므로 백업 또는 사용자 재연결이 필요하다.
- AES-256-GCM, 매 암호화마다 새 IV, 회원 ID와 필드 용도를 AAD에 결합한다. APPKEY/Secret/토큰을 모두 암호화한다. 토큰 만료시각만 평문 저장한다.
- 운영 화면은 HTTPS로 제공한다. API HTTP wire/debug 로깅과 프록시 요청 본문/전체 URL 로깅을 켜지 않는다. 공식 토큰 API는 키를 쿼리 파라미터로 요구하므로 URL 자체가 비밀이다.
- 실제 API 키를 이용한 종단 검증과 운영 DB 적용은 이 코드 변경에 포함되지 않는다.

## 조회 및 반영 계약

- HTTP 대상은 `https://api.nhplug.com:8443` 고정. 주문/출금 경로는 허용하지 않는다. 키 자체의 조회 전용 권한을 보장하는 것은 아니다.
- 운영 일반 계좌(`acct_type=01`)만 노출하며 모든 잔고/거래 요청 직전에 해당 사용자의 API 계좌 목록으로 소유권을 다시 확인한다. 대리 로그인은 연결 화면 접근을 거부한다.
- 토큰은 암호화 DB 캐시를 재사용하며 회원 행 잠금으로 만료 시 재발급을 직렬화한다. 401은 한 번 갱신 후 재조회, 429는 재발급하지 않는다. 연결/읽기 timeout은 5/12초다.
- 단일 앱 인스턴스의 API 요청 간격은 250ms 이상. 다중 인스턴스 배포 시 공급자 유량에 맞는 공유 제한이 추가로 필요하다.
- 연속조회 헤더 cts/cts_flag와 연속 응답코드를 확인한다. 커서 누락·반복·30페이지/1만 건 초과 시 부분 내역을 성공으로 반환하지 않는다.
- 문서화된 완료/정상/빈 결과 메시지만 허용한다. 확인하지 못한 새 메시지는 빈 결과로 간주하지 않고 오류로 표시한다. 실계좌 검증에서 확인된 정상 응답 문구는 합성 fixture와 함께 확장한다.
- 잔고는 국내 및 미국/일본/홍콩/상해/심천 조회를 제공한다. 평균 단가·매입 환율은 공급자 값이며 가격 소수4자리/환율 소수6자리로 반올림한다. 원화 원금은 기존 보유분 서비스 산식을 따른다.
- 종목 코드/통화가 활성 마스터와 정확히 하나 연결되는 경우만 반영한다. 국내 A+6자리 코드는 접두사만 제거한다. 국내 미등록 코드는 나무 공개 종목 마스터에서 확인한 종목명·시장·ETF 구분으로 필요한 종목만 등록한다. 237바이트 레코드·CP949·LF를 검증하고 시장 1/4 및 ETF 구분 8을 사용한다. 목록은 6시간 캐시하며 조회 실패는 60초 동안 재요청하지 않는다. 비활성 종목은 자동 활성화하지 않는다. ISIN·거래소 불명확·중복 유형은 추측하지 않고 안내한다. 같은 종목 여러 행은 합산을 추정하지 않는다.
- 보유분 미리보기는 사용자·세션·확정 토큰·10분·당일 제한을 갖는다. 선택 행은 서버 미리보기에서 읽으며 전체 트랜잭션으로 저장한다. 미선택/조회에서 사라진 종목은 자동 삭제하지 않는다.
- 월별 거래는 `/common/inquiry/v1/totalTransaction`의 매매 구분(03), 국내(01)/해외(15)로 조회한다. 조회일과 실거래일을 함께 표시하며 통화를 섞어 합산하지 않는다.
- 이 응답에는 고유 체결 ID가 없으므로 장부 자동 저장/중복 판별은 제공하지 않는다. 현재 잔고 기준과 과거 매매가 중복 합산되지 않는다. 향후 체결 ID 기반 수입을 추가할 때 기준 시각/수정체결 정책을 함께 구현해야 한다.

## 국내 종목 코드 중복 처리

같은 코드·통화로 여러 활성 종목이 조회되면 나무 공식 목록의 시장과 종목 유형에 모두 일치하는 기존 항목이 정확히 하나일 때만 선택한다. 예를 들어 KOSPI/STOCK과 ETF/ETF가 함께 있고 공식 분류가 ETF이면 ETF/ETF 항목을 사용한다. 기존 종목·거래 참조를 삭제하거나 병합하지 않는다. 공식 목록을 확인하지 못하거나 일치 항목이 하나가 아니면 임의의 첫 항목을 선택하지 않는다.

## 다중 사용자 서비스 제공 전

공개 이용 안내에서 사용자별 API 신청 절차는 확인했지만, 외부 서비스가 다수 사용자의 키를 수탁하여 조회하는 범위는 확정하지 못했다. 공개 운영 전에 나무의 실제 신청 약관 및 고객지원으로 해당 운영 형태의 허용 여부를 확인한다. 이는 자동 허용/금지라는 판단이 아니다.
