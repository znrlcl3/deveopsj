# 종합잔고 먼저 등록하기

내 자산 → 잔고 가져오기(`/holdings/import`)에서 계좌에 해당하는 자산 플랜과 실제 잔고 조회일을 지정하고 나무증권 종합잔고 원본을 업로드한다. 파일 자체에는 계좌 식별값이나 기준일이 없으므로 사용자 선택이 필요하다. 5MB·2,000행 이하의 HTML XLS(MS949/UTF-8) 또는 단일 시트 XLS/XLSX를 지원한다. 수식은 거부한다.

## 저장과 조회

- 상단 자산금액·매입금액·평가금액·평가손익·예수금·D+1/D+2·외화예수금을 원본대로 보관한다. 계좌 총액은 상단 자산금액이며 예수금을 다시 합산하지 않는다.
- 행의 상품코드(국내 6자리 또는 해외 ISIN), 잔고유형, 현금/소수점 구분, 소수점 수량, 가격, 원화 매입/평가/손익, 수익률을 구조화하여 저장한다. 원본 바이트도 보존하고 본인만 다운로드할 수 있다.
- 같은 상품코드의 현금·소수점 행은 별도 원본으로 유지하고 고유 보유종목 수에서는 하나로 센다. 종목 마스터와의 연결은 필수가 아니다.
- 계좌별 최신 파일의 자산금액을 합산한다. 서로 다른 기준일이나 증권사 합계와 행 합계의 차이를 숨기지 않는다. 파일 값이며 현재 시세가 아니다.
- 동일 계좌·기준일·파일 SHA-256은 중복 저장하지 않는다. 같은 기준일의 수정 파일이나 이후 기준일의 파일은 기존/신규 상세를 비교하고 명시적으로 확인한 뒤 새 버전으로 저장한다. 이전 버전은 삭제하지 않는다. 기준일 역행은 차단한다.
- 갱신은 계좌 파일 전체 단위이다. 새 파일에서 사라진 종목은 최신 표시에서도 사라진다. 매매 행이나 기존 직접 입력 기록을 삭제하지 않는다.
- 세션 미리보기 10분, CSRF, 본인 계좌 검사, 계좌 잠금, 저장 후 토큰 소비, 이전 버전 ID 검사로 위조·재전송·동시 갱신을 방지한다.

## 매매내역으로의 확장 경계

잔고는 `account_balance_snapshot`에 독립 저장한다. 기존 `AssetTrade`의 매수 또는 SNAPSHOT으로 변환하지 않는다. 해외 외화 매입원가·실제 매입환율은 없는 값으로 남겨야 하며 원화 원가에서 임의로 역산하지 않는다. 현 버전은 잔고 등록 이후 매매를 잔고에 자동 가감하지 않는다. 기존 거래 업로드/조회는 계속 사용할 수 있으나 화면에서 잔고 파일 총액과 별도 표시하고 합산하지 않는다.

후속 구현은 종목코드/ISIN 연결, 계좌별 기준일 정책을 먼저 확정한 뒤 기준일 이후 거래만 적용해야 한다. 원본의 기준일 당일 거래 포함 범위와 미결제/예수금 정산을 확인하고, USD 원가 미상 상태를 유지하며 재조회 잔고와 대조해야 한다. 새 잔고에서 누락된 종목의 잔량은 0으로 재설정하되 거래 이력은 유지한다.

## DB 및 검증

운영 validate 환경에는 `deploy/sql/20261110_add_account_balance_snapshot.sql`을 한 번 적용한다. 기존 테이블·데이터 변경은 없다. 로컬 ddl-auto=update 환경은 재시작 시 테이블을 생성한다. SQL 파일 작성과 실제 DB 실행은 별도이며 이번 작업에서 실제 DB에는 적용하지 않는다.

합성 데이터 테스트는 숫자 정밀도·원본 차이 보존, 재업로드 확인, 중복·오래된 미리보기, 타인 접근, CSRF, 토큰 재사용 및 화면 렌더링을 검증한다. 실제 잔고 파일은 읽기 전용 파싱으로 확인하고 테스트 fixture로 복사하지 않는다.
