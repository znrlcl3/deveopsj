# 삼성카드 할부 예상 지출

`일시불+할부_카드이용내역조회.xlsx`의 할부는 승인총액을 개월 수로 나눈 **예상 원금**이다.
수수료·할인·실제 청구 회차는 알 수 없으며, 실제 청구액으로 간주하지 않는다.

미리보기에서 첫 청구일(파일의 결제일을 제안), 전체 회차별 날짜·금액을 확인하고
거래 선택과 예상액 확인 체크를 모두 해야 등록된다. 결제일이 없으면 직접 입력한다.
1원 미만 나머지는 마지막 회차에 더하며, 월말 결제일은 각 월 말일로 조정한다.

각 회차를 해당 월에만 적용되는 고정지출 규칙으로 저장한다. 실제 지출은 만들지 않는다.
지출 목록의 고정지출·할부 예정에서 해당 월 청구액을 확인한 뒤 확정한다.
금액이 다르면 고정지출 관리에서 해당 회차 금액을 수정하고, 불필요한 회차는 중지한다.
예상액 수정으로 다른 회차 금액을 자동 재분배하지 않는다. 미래 월 할부는 확정할 수 없다.
청구명세서로 이미 등록한 거래는 선택하지 않는다. 이후 청구명세서를 가져올 때도 중복 여부를 확인한다.
취소 거래 업로드는 기존 지출이나 예정 규칙을 자동 삭제하지 않는다. 남은 회차는 직접 중지한다.

## DB 적용 순서

운영 배포 전에 기존 DB 백업 후 `deploy/sql/20261021_add_card_installment_schedule.sql`을
대상 DB에서 **한 번만** 실행한다. 적용 여부는 `SHOW COLUMNS FROM recurring_expense LIKE
'card_installment_key'` 및 `SHOW INDEX FROM recurring_expense`로 확인한다.
SQL은 자동 실행되지 않으며 실제 DB에는 이 작업에서 적용하지 않는다.

추가 컬럼은 NULL 허용이며 기존 규칙은 그대로 유지된다. 회원·회차별 키의 유일 제약으로
재업로드·동시 등록 시 중복을 차단한다. 충돌하면 일시불을 포함한 업로드 전체가 롤백된다.
첫 청구일을 바꾸거나 예정 규칙을 중지해도 재업로드로 같은 할부를 다시 만들 수 없다.
각 회차의 적용 월은 고정되며 금액·메모·결제일은 확정 전에 수정할 수 있다.

테이블 ALTER는 MySQL 메타데이터 잠금이 필요하므로 긴 트랜잭션이 없는 시간에 적용한다.
실패하면 컬럼·인덱스 상태를 확인한 뒤 미적용 부분만 적용하며 전체 SQL을 재실행하지 않는다.
코드 롤백 시 추가 컬럼은 남겨 두어도 이전 코드에 영향이 없다. 예정 데이터는 보존하고
컬럼을 제거해야 한다면 먼저 신규 코드 사용을 중지하고 데이터 백업·복구 계획을 수립한다.
