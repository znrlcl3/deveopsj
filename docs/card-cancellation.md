# 신한카드 취소 반영

배포 전에 백업 후 `deploy/sql/20261105_add_card_cancellation.sql`을 한 번 적용한다.
실제 DB 적용은 별도 작업이다. 기존 `daily_spending`에 버전 열을 추가하므로 구버전 앱과 동시 쓰기를 하지 않는다.

- 음수 취소 행의 **기존 지출 찾아 취소 반영** 링크에서 후보를 확인한다.
- 후보는 본인의 같은 가맹점명, 취소일 이전, 충분한 잔여 금액의 신한카드/직접 입력 거래 최근 20건이다. 승인번호가 저장되지 않은 기존 내역이므로 자동 매칭을 보장하지 않는다.
- 다른 카드사, 반복 규칙, 할부 예정은 제외한다. 후보가 없으면 가맹점명과 원거래를 직접 확인한다.
- 사용자가 원거래와 취소 후 금액을 확인한 건만 반영한다. 기존 지출의 날짜와 카테고리는 유지하며 **원거래 월**의 지출이 줄어든다.
- 전액취소도 0원 원거래를 유지한다. 기존 카드 거래 키를 보존하여 원승인 재업로드를 막는다. 내역 건수에는 0원 기록도 포함된다.
- 같은 취소 거래 키는 사용자별 유일 제약으로 중복 차감을 방지한다. 원거래 잠금·버전 검증과 취소 이력 저장은 같은 트랜잭션이다.
- 이미 수동 차감한 취소는 자동 판별할 수 없다. 확인 없이 적용하지 않는다.
- 승인번호/시간/금액 등이 바뀐 수정 파일은 다른 거래 키가 될 수 있다. 같은 취소인지 확인해야 한다.
- 취소 이력은 원거래 금액 전후와 시점을 보존한다. 원거래를 수동 삭제하더라도 취소 이력은 남는다. 이력 삭제나 자동 되돌리기는 제공하지 않는다.
- 오류 시 취소 이력과 금액 변경이 함께 롤백된다. 앱 롤백 시 이력 테이블·버전 열은 보존한다.
